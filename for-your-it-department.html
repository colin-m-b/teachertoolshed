Teacher Toolshed For your IT department

Technical and legal summary

One page for the person who has to approve this

Everything a vendor review normally asks, answered once. The short version: the site runs in the teacher's browser, keeps student data there, and has no server that could receive it.

What it is

Teacher Toolshed is a static website: HTML, CSS and JavaScript files served from a content host. There is no application server, no database, no user accounts, no sign-in and no analytics. Every tool runs entirely in the browser that loaded it.

The first three rows never touch a server operated by the site. The last two contain no student data and exist only for teachers who buy Pro.

What is transmitted

  • Page loads only. Every page, font, stylesheet and code library is served from the site's own origin. A page makes no request to any other domain. This is enforced by a Content-Security-Policy header of default-src 'self'.
  • The one exception, Pro only: when a teacher enters a licence key, the browser sends that key to the merchant of record's licence endpoint to confirm it is valid, and repeats the check roughly every 30 days. The request contains the key and a device label such as "Chrome on Windows". It never contains an email, a roster, or anything typed into a tool. A key that cannot be re-checked keeps working for 90 days, then the tools fall back to the free tier without touching any data.
  • Nothing else. No telemetry, no crash reporting, no error beacons, no cookies.

Student-facing pages

Two pages are opened by students: the hexagonal-thinking canvas and the Pure Writer writing page. They load no licence code, make no network request after loading, and set no cookies. A student never creates an account or enters anything beyond the name and ID their teacher asked for, which stays on their device.

FERPA

Because no education record is transmitted to, stored by, or accessible to the site's operator, the operator does not receive or maintain education records and is not a "school official" with access to them under 34 CFR 99.31. The data never leaves the teacher's device, so the teacher's own school policy on device storage is the governing one. State student-privacy laws that regulate operators who collect student data (for example NY Education Law 2-d, Illinois SOPPA, California SOPIPA) are, for the same reason, not triggered: there is no collection.

GDPR and UK GDPR

For the free tools the site processes no personal data at all: no request carries any, no cookie is set, and the fonts and libraries are self-hosted so no IP address reaches a third party. For Pro, the site's author is a data controller for one category of data subject, the purchasing teacher, on the basis of the contract of sale, with the merchant of record as the processor and seller. No child's data is processed in any role. Data-subject requests are handled by email: the author deletes the correspondence and asks the merchant of record to delete the customer record.

Planned: sync through the teacher's own cloud drive

A later Pro feature will let a teacher keep a copy of their data in their own Google Drive or OneDrive. The design is fixed now so it can be reviewed early: the browser obtains an OAuth token directly from Google or Microsoft (scope drive.appdata / Files.ReadWrite.AppFolder, both app-private folders), writes the same JSON file the Export button already produces, and reads it back on another device. The token and the file never pass through a server operated by the site. School-managed Google or Microsoft accounts fall under the school's existing Workspace or 365 agreement; a school that blocks third-party OAuth simply keeps using JSON export.

Things you can verify yourself

  • Open any tool with the browser's developer tools on the Network tab: after the page's own files, there are no requests.
  • Read the response headers: Content-Security-Policy: default-src 'self' ….
  • The full source is the site. There is no server-side code to ask about.
